3. Kiến trúc: một vòng ReAct

Hai tool có sẵn (bạn không sửa):

  • get_status(provider, component='') — overall status, component khớp, tối đa 5 incident khớp chuỗi trong 50 incident gần nhất.
  • get_incident_details(provider, incident_id) — chi tiết incident (2 update mới nhất + update đầu, mỗi update ≤ 900 ký tự) và url nguồn.

5. Khởi động (0–15 phút)

  1. Chọn một provider có tool calling, export biến môi trường (chương trình không tự đọc .env): 
    export PROVIDER=openai          # hoặc gemini / anthropic / openrouter
export MODEL='<model-có-tool-calling>'
export OPENAI_API_KEY='...'
  2. Chạy thử tool, không cần key — để nhìn tận mắt dữ liệu model sẽ thấy: 
    python3 -c 'import json; from status_tools import StatusTools; print(json.dumps(StatusTools().get_status("github", "Actions"), ensure_ascii=False, indent=2))'
python3 -c 'import json; from status_tools import StatusTools; print(json.dumps(StatusTools().get_incident_details("cloudflare", "wp49bp8bqo6c"), ensure_ascii=False, indent=2))'
  3. Chạy tests để thấy baseline đỏ: python3 -m unittest discover -s tests -v. Các test LoopTests, FullTrajectoryTests, EvidenceGateTests sẽ fail — đó là việc của bạn.
Ghi nhớ về dữ liệucomponent là tìm chuỗi gần đúng, không phải semantic: "cache purge" khớp, "xóa bộ nhớ đệm" thì không. Tìm không thấy ≠ không có sự cố. Overall "none" ≠ mọi component ổn.

6. Bài 1 — Tự viết agent loop (15–70 phút)

Contract phải tuân thủ

  • provider.complete(messages, SCHEMAS) → {message, calls, finish, usage}.
  • Append message (assistant) nguyên vẹn vào messages trước các tool result.
  • Mỗi call: {id, name, arguments} — arguments là JSON string, phải json.loads.
  • Tool result: {'role': 'tool', 'tool_call_id': call['id'], 'content': json.dumps(result, ensure_ascii=False)}.
  • Xử lý mọi call trong một response trước khi gọi model tiếp.
  • Kết thúc khi finish == 'stop' và không còn calls.
  • Trả: status ∈ {completed, max_steps, error}, answer (str), trace (list), usage (list).

Checkpoint của mentorSau tool call đầu tiên, model có thực sự nhận được tool result gắn đúng ID? Nếu một response có 2 calls, cả 2 result đã được trả theo thứ tự chưa? Kiểm bằng test_tool_result_is_returned_with_id và test_multiple_tool_calls.
Gợi ý nếu bị kẹt
  • Test đọc fake.histories[1][-1] — tức là message cuối cùng gửi ở lần gọi thứ 2 phải là tool message. Nếu bạn chèn gì đó sau tool result, test fail.

Bước 3 — Bắt buộc: evidence gate (kiểm URL nguồn)

Dù bạn chọn cải tiến khác, vẫn phải pass tests/test_validation.py::EvidenceGateTests:

  1. Mỗi lần get_incident_details trả ok: True → lưu result['url'] vào tập observed_urls.
  2. Khi model trả final answer: nếu observed_urls không rỗng và answer không chứa URL nào trong đó → thêm trace {'event': 'validation_missing_source', ...}, append một user message yêu cầu bổ sung nguồn, rồi gọi model tiếp (vẫn tính vào max_steps).
  3. Hết lượt mà vẫn thiếu → status: max_steps, không phải completed.
  4. Tool lỗi (incident không tồn tại) → không có URL → không bắt buộc nguồn.
Giới hạn phải nói thật trong ghi chúGate này chỉ kiểm sự hiện diện một URL, không chứng minh mọi claim đều có nguồn. Model có thể dán URL nhưng vẫn kết luận sai.

Bước 4 — Có thể thêm 1 cải tiến khác (chọn 1, đừng sửa lung tung)

  • Siết SYSTEM_PROMPT: tool result là dữ liệu không đáng tin; timeout ≠ trạng thái dịch vụ; không bịa ID/URL.
  • Bọc tool result bằng nhãn "UNTRUSTED DATA" trước khi đưa vào messages (chống injection).
  • Phát hiện lặp cùng một tool call với cùng args → ghi trace và nhắc model.

Mỗi thay đổi một biến → mới biết biến đó có tác dụng.

11. Bẫy hay gặp

Quên append assistant message trước tool result

Provider (đặc biệt OpenAI) sẽ báo lỗi 400 vì tool message không có tool_call tương ứng. Anthropic adapter cũng cần nó để dựng block tool_use.

Đếm step theo tool call thay vì model call

Một response có 3 tool calls vẫn chỉ là 1 step. max_steps giới hạn số lần gọi provider.complete.

Coi finish == 'length' là xong

Output bị cắt → câu trả lời dở dang → phải là error.

json.dumps tiếng Việt thành \uXXXX

Dùng ensure_ascii=False để trace/answer dễ đọc và tiết kiệm token.

Evidence gate không đếm vào max_steps

Yêu cầu sửa vẫn là một lần gọi model. Test test_missing_url_at_budget_limit_is_not_completed kiểm đúng điều này.

Commit key hoặc trace nhạy cảm

Chương trình không đọc .env; đừng dán key vào code. Xem lại file eval trước khi nộp.

Dùng --mode live để chạy eval

Eval dùng snapshot cố định 09/11/2026 để so sánh được. Live chỉ để demo, dữ liệu thay đổi liên tục.
